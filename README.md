# モンスターバトル オンライン版

シャドウバース風の2人対戦カードゲームです。フォロワー（モンスター）を場に出して戦わせ、相手リーダーのHPを0にしたら勝ちです。
別々のスマホ／PCから、ルームコードで同じ試合に入って対戦できます。CPU対戦（1人用）も入っています。
基盤（Node.js＋WebSocketのサーバー審判方式・ルームコード対戦）は「カードバトル オンライン版」から流用し、ゲームルールを差し替えた新規プロジェクトです。
**このフォルダは「無料サーバーへデプロイする直前」の状態です。デプロイ作業（アカウント作成・公開）はまだ行っていません。**

## 遊び方（ルール概要）

- お互いリーダーHP20・手札4枚・デッキ30枚でスタート。先攻・後攻あり。
- エネルギー（PP相当）はターン開始時に最大値+1（上限10）＆全回復。初手の上限は1から増えていきます（自分のターン数＝最大エネルギー）。
- ターン開始時に1枚ドロー（先攻の1ターン目のみドローなし）。手札上限は9枚（あふれた分は捨て札へ）。
- 山札が尽きたら捨て札をシャッフルして再利用。それもなければ引くたびに1ダメージ。

### フォロワー（モンスター）
- コスト／攻撃力／体力を持ち、場に出ると残り続けます。各プレイヤーの場は最大5体。
- **召喚酔い**：出したターンには攻撃できません。ただし **疾走** 持ちは出したターンから攻撃できます。
- **攻撃**：自分のターンに各フォロワーは1回まで、相手フォロワーか相手リーダーを攻撃対象に選べます。フォロワー同士の戦闘は攻撃力分を同時に与え合い、体力0以下で破壊されて捨て札（墓地）へ送られます。
- **守護**：守護持ちが場にいる間、相手はリーダーや他のフォロワーを攻撃できず、守護を攻撃しなければなりません。
- **ファンファーレ**（場に出たとき）と **ラストワード**（破壊されたとき）の効果を持つフォロワーがいます。
- 進化（エボルヴ）はありません。

### スペル
- ファイアボール（単体3ダメージ）、必殺の一撃（単体破壊）、メテオ（相手全体3ダメージ）、スマイト（リーダー4ダメージ）、ヒール（リーダー4回復）、パワーアップ（自分のフォロワー+2/+2）の6種。
- 対象を取るスペルは、カードを選んだあとに対象のフォロワーをタップして発動します。

### カードプールとデッキ
- フォロワー13種＋スペル6種＝19種。標準デッキは30枚（フォロワー23枚＋スペル7枚）です。
- 絵柄は軽量化のため、絵文字1文字＋色分けのみで、画像ファイルは使っていません。

### カード編集とデッキ保存
- モード選択の「カード編集・デッキ」から、全カードの名前・アイコン（絵文字1文字）・色・コスト・説明文と、フォロワーの攻撃力／体力／守護・疾走／ファンファーレ・ラストワード（種類と数値）、スペルの効果（種類と数値）を編集できます。
- **カードの種類を増やせます**：「＋ フォロワーを作成」「＋ スペルを作成」ボタンで新規カードを追加でき（初期値はフォロワー＝コスト2・攻撃2・体力2・効果なし、そのまま編集可能）、各カードには「複製」（名前は「○○ のコピー」）と「削除」もあります。新規カードのIDは `custom_…` 形式で自動採番され、カードは最大64種まで作れます。削除したカードはデッキからも自動で外れ、合計が30枚未満になると理由が表示されて保存できなくなります（そのまま対戦に入ると標準デッキ＋本人通知にフォールバックします）。トークン（ミニスライム）は編集・削除できません。
- 編集したカードプールから30枚ちょうどのデッキを組めます（同じカードは最大3枚まで）。30枚でない・上限超過のときは理由が表示され、保存できません。
- 保存先はブラウザの localStorage で、次回もそのまま使えます。「標準に戻す」で標準カード・標準デッキへ戻せます。編集データの書き出し（JSONファイル＋テキスト）／読み込みにも対応しています。
- 対戦への反映：CPU対戦ではプレイヤーが保存デッキ、CPUが標準デッキを使います。オンライン対戦では各プレイヤーが自分の保存デッキを持ち込みます。
- オンラインの持ち込みデータはサーバー側でも検証・サニタイズします（コスト0〜10、攻撃0〜15、体力1〜20、効果数値にも上限あり。スペルの対象要否は効果からサーバーが決め直します）。不正・不成立の場合は標準デッキにフォールバックし、本人に通知します。編集していない場合は従来どおり標準カード・標準デッキで遊べます。

### 勝敗
- リーダーHPが0以下で負け。同時に両方0になった場合は手番プレイヤーの勝ちです。
- 降参もできます（自分のターンでなくても降参できます）。

### オンライン対戦の流れ

1. どちらかが「オンライン対戦」→「ルームを作る」。相手が参加するまで、4文字のルームコードを大きく表示する待機画面が出ます。
2. そのコードを相手に送り、相手が「コードで参加する」から入力すると対戦開始。
3. 自分の手札からカードを出し、フォロワーをタップ→攻撃対象をタップで攻撃。「ターン終了」で交代。
4. 決着後は「もう一戦」でそのまま再戦できます。

### CPU対戦
- 「CPU対戦」からすぐ遊べます。CPUは出せるフォロワーを出し、除去スペルで守護や強敵を処理し、攻撃できるフォロワーで（守護がいれば守護へ、いなければ有利な戦闘かリーダーへ）攻撃する簡易AIです。

## 構成

```
monster-battle-online/
├─ server.js        … HTTP配信＋WebSocketサーバー（審判役）
├─ game.js          … ゲームロジック（サーバー側・各プレイヤー向け表示生成）
├─ public/
│  └─ index.html    … クライアント（単一HTML。CPU対戦用のローカルエンジンも同梱）
├─ test/
│  ├─ test.js       … 自動テスト（単体：ルール/効果、統合：2クライアント対戦フロー）
│  ├─ multi-room-test.js … 複数ルーム同時進行テスト（3ルーム＝6台）
│  ├─ client-test.js … クライアント画面テスト（DOMスタブ＋実サーバー接続）
│  └─ TEST_RESULTS.md … テスト結果の記録
├─ package.json
└─ README.md
```

### 仕組みのポイント
- **状態はサーバーが一元管理（審判方式）**します。クライアントは「カードを出す」「攻撃する」「ターン終了」といった操作だけを送り、結果の計算はすべてサーバー側です。不正な操作（相手ターン中のカード使用、守護を無視した攻撃、召喚酔い中の攻撃など）はサーバーがエラーで弾きます。
- **手札などの秘匿情報は本人のクライアントにだけ送ります。** 相手には手札の「枚数」と山札枚数だけが届きます（場のフォロワーは公開情報なので両方に見えます）。`game.js` の `viewFor()` で送信データを組み立てています。
- **再接続**：入室時に発行されるプレイヤーIDをブラウザ（localStorage）に保存し、回線が切れても同じルームに同じ席で復帰できます（ロビーの「前の対戦に戻る」から）。

## ローカルでの動かし方

前提：Node.js 18以上

```bash
cd monster-battle-online
npm install   # 初回のみ（ws を取得）
npm start     # サーバー起動（http://localhost:3000）
```

ブラウザを2つ（またはスマホとPCなど）で `http://localhost:3000` を開き、
1人目が「ルームを作る」→表示された4文字コードを、2人目が入力して「参加する」を押せば開始です。
（同じPCで試す場合は、別ウィンドウやシークレットウィンドウを使うと楽です。CPU対戦は1人ですぐ遊べます）

自動テスト：
```bash
npm test           # 単体＋統合テスト（132件）
npm run test:multi # 複数ルーム同時進行（9件）
npm run test:client # クライアント画面テスト（46件）
```

## Render 無料枠へのデプロイ手順（ここから先はユーザーの作業）

> アカウント作成とデプロイは、ご自身で行ってください。以下は手順書です。

1. https://render.com でアカウントを作成（GitHubアカウントでサインアップが楽です）。
2. このフォルダ（monster-battle-online）を、ご自身の GitHub リポジトリにアップロード（push）します。
3. Render のダッシュボードで **New → Web Service** を選び、そのリポジトリを接続します。
4. 設定値：
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
5. **Create Web Service** を押すとデプロイが始まります。数分で `https://（サービス名）.onrender.com` のようなURLが発行されます。
6. そのURLをふたりのスマホで開けば、どこからでも対戦できます（WebSocket は自動で wss 接続になります）。

※ Render の無料枠を使わず、自分のPCで動かし続ける方法でも遊べますが、その場合はPCの電源とネット接続が必要です。

## 注意点（大事）

- **無料枠は約15分アクセスがないとスリープ**します。次に開いたときの初回表示に30〜60秒ほどかかることがあります。
- **サーバーが再起動するとルームは全部消えます**（状態はメモリ上だけに保持しているため）。スリープからの復帰＝再起動なので、対戦中にスリープすると試合はリセットされます。遊ぶ直前にページを開いて「起こして」おくのがおすすめです。
- ルームコードは4文字の簡易なものです。知らない人が偶然入ってくる可能性がゼロではないので、コードは遊ぶ相手だけに共有してください（本格的な認証はありません）。
- **複数ルーム同時対応**：サーバーは複数のルームを同時並行で処理できます。状態が混ざらないことを自動テスト（`npm run test:multi`）で確認済みです。ゲームの状態は軽量（1ルームあたり数KB程度）なので、友達同士の規模なら無料枠の性能で十分です。安全のためルーム数の上限は50に設定してあり、30分間誰も接続していないルームは自動で片付けます。
- データの永続化（戦績保存など）は未実装です。
- クライアントは単一HTMLファイル構成のため、CSS/JSは別ファイルではなくHTML内に含まれています。CPU対戦はブラウザ内のローカルエンジン（game.js と同じルールの移植）で動作し、サーバー接続は不要です。

## カードバトル オンライン版との差分

- リーダーHP30→20、デッキ32枚→30枚、手札上限8枚→9枚、エネルギー上限8→10（初手の最大値は2→3ではなく、ターン数どおり1から）。
- 攻撃カードで直接殴り合う方式から、フォロワーを場に残して戦わせる方式に変更（召喚酔い・疾走・守護・ファンファーレ・ラストワードを追加）。毒・シールド・貫通の仕組みは本作にはありません。
- カード編集は本作にもありますが、方式が異なります。カードバトルは「ホストの編集セットを両者が使う」方式、本作は「各プレイヤーが自分の編集カード＋自作デッキを持ち込む」方式です。
- 同時に両者HP0になった場合は「手番プレイヤーの勝ち」（カードバトルは手番プレイヤーの負けだった点が異なります）。

## デプロイ後にやりたいこと（任意）

- Render の有料プランや常時起動のVPSに移すと、スリープとルーム消滅が解消します。
- 状態をデータベース（Render の PostgreSQL 等）に保存すれば、再起動しても試合を継続できます（要改修）。
